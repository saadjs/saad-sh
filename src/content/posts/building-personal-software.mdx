Thanks to AI, building personal software has never been easier!

Build the thing you want. Run it. Fix it. Keep it.

Also, it feels the world wide web is filled with cookie banners, ads, annoying popups and everyone wants me to "Sign-In using Gmail" 🙄.
So it feels good to visit something you/your agent 🤖 built which has none of this 💩. And most of the software we use daily rarely feels **personal**.

Most projects start with someone wanted to solve a specific problem but then had to add ton of features to fit other users, which may lead to other frustrations. So we have to use the software how they want and not the other way around.

## Build for your own taste

Most of what I build starts as something that annoyed me:

- [kcal-cli](https://github.com/saadjs/kcal-cli) so personal agents, e.g. [Neo](/posts/building-personal-ai-assistant), OpenClaw, etc., can log my food and macros for me, no app to tap through. All I need to do is post the picture of meal and rest is handled 😇.
- [In Days](https://saadjs.github.io/in-days-docs/features.html) so I can keep track of my office days 🏢.
- [Runway](https://github.com/saadjs/Runway) because I wanted my Claude and Codex usage in the menu bar.
- [Pace to MPH](https://github.com/saadjs/pace-to-mph) because I wanted running speed in MPH and not just pace without opening an ad-soaked app-store apps and see the data in the format I want 🏃.
- [ViewMD](https://github.com/saadjs/view-md) because Markdown files should preview cleanly from Finder.

And a few more.

None of these need to fit anyone's workflow but mine and that is the whole point. And sometimes all it needs is 2-3 prompts 🤯.

## Keeping the scope small

The easiest way to ruin a useful tool is to imagine an audience before you have a working loop.

Do not build the product other people might want. Build the thing you need this week or need it today! If it survives contact with your actual life, your family, then you can make it nicer, add other features that feel like _"Oh, this would be nice to have with this"_.

This is where AI helps. The bottleneck used to be time. Many nights or weekends before the project became useful, or give up because it took too long to get there. Now I can just hand a cloud agent a problem, let it build and deploy while I do something else, then come back and verify that it works the way I wanted.

Time is no longer the bottleneck. Finding problems I want to solve and what to build is 😄.

## Forking

Starting from scratch is overrated. Sometimes the fastest path is a fork.

If an open source project does 80% of what you want, fork it. Rip out the parts you do not use. Add the one thing you wanted in the first place. Run your version.

e.g. [FlightDeck](https://github.com/saadjs/FlightDeck) exists because AeroSpace was blocked at my company. The maintainer had a strong position on Apple and did not want to notarize it. I forked it, notarized it, got it approved by enterprise security, and now anyone who hits the same wall can use it.

This used to be annoying. You would spend the evening reading someone else's codebase just to find the right file. Now I point Codex or Claude at the codebase, rip out what annoys me, and add what I want.

## Build it this weekend

Pick the next small thing that annoys you.

Build the tool you wish existed, or fork the one that is close and make it until it fits your needs, make it yours.

Once you do this a few times, software stops feeling like something you wait for other people to build. And it will be personal ❤️.

Happy Prompting/Coding!
